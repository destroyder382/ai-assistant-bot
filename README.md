# AI Assistant Bot

Телеграм-бот с ИИ-ассистентом на Python. Отвечает через LLM API (Groq), помнит контекст диалога, умеет отвечать по загруженному пользователем текстовому документу (RAG) и собирает простую статистику.

## Возможности

- ответы на обычные сообщения через LLM (Groq, OpenAI-совместимый клиент)
- память диалога для каждого пользователя (последние 20 сообщений), история хранится в SQLite
- **ответы по документу (RAG):** пользователь присылает боту файл `.txt`, бот режет его на фрагменты, сохраняет в SQLite и при каждом вопросе подставляет в запрос к модели подходящие фрагменты; если подходящих нет, отвечает как обычный ассистент
- у каждого пользователя свой документ, новая загрузка заменяет предыдущий
- защита при загрузке: только `.txt`, размер до 1 МБ, кодировка UTF-8, пустые файлы отклоняются
- обработка ошибок API: при сбое бот отвечает понятным сообщением, а не молчит
- статистика через SQL: пользователи, количество вопросов, активность по дням, средняя длина ответа

## Команды

| Команда | Что делает |
|---------|-----------|
| `/start` | приветствие |
| `/reset` | очищает историю диалога пользователя |
| `/myid` | показывает твой Telegram ID |
| `/stats` | статистика по боту (только для администратора) |

Чтобы бот отвечал по документу, пришли ему текстовый файл как файл (скрепка, «Файл»), а потом задавай вопросы по его содержимому.

## Стек

Python, aiogram 3, OpenAI SDK (подключён к Groq), SQLite.

## Запуск

1. Установи зависимости:

```
pip install aiogram openai
```

2. Скопируй `config.example.py` в `config.py` и впиши значения:

- `TOKEN` — токен бота от @BotFather
- `GROQ_API_KEY` — ключ с console.groq.com (есть бесплатный тариф)
- `ADMIN_ID` — твой Telegram ID (узнай командой `/myid`, затем впиши число)

3. Запусти бота:

```
python bot.py
```

База `bot.db` создаётся автоматически при первом запуске.

## Как работает поиск по документу

1. Загруженный текст режется на фрагменты по 500 символов с перекрытием в 100 символов, чтобы мысль на границе не терялась. Фрагменты сохраняются в таблицу `chunks` вместе с `user_id` и названием файла.
2. Для каждого вопроса считается, сколько слов вопроса встречается в каждом фрагменте. Служебные слова («что», «как», «когда» и подобные) игнорируются, фрагменты без совпадений отбрасываются.
3. Два лучших фрагмента добавляются в запрос к модели вместе с вопросом. В историю диалога при этом пишется только сам вопрос, без фрагментов.

Поиск простой, по совпадению слов, поэтому он не учитывает смысл и формы слов. Улучшение через эмбеддинги в планах.

## Структура

- `bot.py` — хендлеры бота, загрузка документов и запросы к LLM
- `db.py` — работа с SQLite (история диалога, фрагменты документов, статистика)
- `rag.py` — нарезка текста на фрагменты и поиск подходящих
- `config.example.py` — пример конфигурации

## Планы

- поиск по смыслу с помощью эмбеддингов
- запуск на сервере
- поддержка других форматов документов (PDF, DOCX)
- расширенная аналитика по использованию бота
