# AI Assistant Bot

Телеграм-бот с ИИ-ассистентом на Python. Отвечает на сообщения через LLM API (Groq), помнит контекст диалога каждого пользователя, умеет отвечать по текстовому документу (RAG) и собирает простую статистику.

## Возможности

- ответы на обычные сообщения через LLM (Groq, OpenAI-совместимый клиент)
- память диалога для каждого пользователя (последние 20 сообщений)
- история хранится в SQLite (`bot.db`)
- ответы по документу (RAG): бот режет текстовый файл на куски с перекрытием, находит куски, подходящие под вопрос, и передаёт их модели вместе с вопросом; если подходящих кусков нет, отвечает как обычный ассистент
- обработка ошибок API: при сбое бот отвечает понятным сообщением, а не молчит
- статистика через SQL: пользователи, количество вопросов, активность по дням, средняя длина ответа

## Команды

| Команда | Что делает |
|---------|-----------|
| `/start` | приветствие |
| `/reset` | очищает историю диалога пользователя |
| `/myid` | показывает твой Telegram ID |
| `/stats` | статистика по боту (только для администратора) |

## Стек

Python, aiogram 3, OpenAI SDK (подключён к Groq), SQLite.

## Запуск

1. Установи зависимости:

```
pip install aiogram openai
```

2. Скопируй `config.example.py` в `config.py` и впиши значения:

- `TOKEN` — токен бота от @BotFather
- `GROQ_API_KEY` — ключ с console.groq.com (есть бесплатный тариф)
- `ADMIN_ID` — твой Telegram ID (узнай командой `/myid`, затем впиши число)

3. Создай рядом с `bot.py` файл `knowledge.txt` (кодировка UTF-8) и вставь в него текст документа, по которому бот должен отвечать. В репозиторий этот файл не входит. Без него бот не запустится.

4. Запусти бота:

```
python bot.py
```

База `bot.db` создаётся автоматически при первом запуске.

## Как работает поиск по документу

1. При старте `rag.py` читает `knowledge.txt` и режет текст на куски по 500 символов с перекрытием в 100 символов, чтобы мысль на границе не терялась.
2. Для каждого вопроса считается, сколько слов вопроса встречается в каждом куске. Служебные слова («что», «как», «когда» и подобные) игнорируются.
3. Два лучших куска добавляются в запрос к модели. Куски без совпадений в запрос не попадают.

Поиск простой, по совпадению слов, поэтому он не учитывает смысл и формы слов. Улучшение через эмбеддинги в планах.

## Структура

- `bot.py` — хендлеры бота и запросы к LLM
- `db.py` — работа с SQLite (история, статистика)
- `rag.py` — нарезка текста на куски и поиск подходящих кусков
- `config.example.py` — пример конфигурации

## Планы

- загрузка документов прямо через бота и хранение кусков в SQLite
- поиск по смыслу с помощью эмбеддингов
- расширенная аналитика по использованию бота
- запуск на сервере
